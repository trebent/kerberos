The API gateway that guards the gate.

Kerberos puts your services behind one entry point and checks every request before it reaches them. Logins, multi-tenant access control, OpenAPI contract checks and OpenTelemetry come built in, with no plugins or sidecars to assemble.

Three heads, one gateway

Route. Guard. Observe.

Named after the three-headed dog at the gate, Kerberos does the three jobs every API edge needs, in one process with one config file.

01

Route

Register backends by name and reach them at /gw/backend/<name>/….

  • Per-backend timeouts
  • HTTPS and mutual TLS to backends
  • Per-backend CORS policies
02

Guard

Decide who gets through, and what a valid request looks like.

  • Cookie sessions with CSRF protection
  • Organisations, users and groups
  • OpenAPI 3 request validation
03

Observe

See traffic, errors and the path each request took.

  • OpenTelemetry traces and metrics
  • Ready-made Grafana dashboards
  • Per-request debug sessions
How it works

Every request takes the same path.

A request is rejected at the first stage that says no, so your backend only ever sees traffic that passed every check you configured.

Configure

One JSON file. No surprises.

The whole gateway is described in a single config file, validated against a JSON schema at startup, so an unknown or misspelt key stops the process with a clear error.

  • Pull secrets from the environment with ${env:NAME}
  • Keep names in sync with ${ref:path.to.field}
  • Start with SQLite, move to PostgreSQL to scale out
krb.json
{
  "gateway": { "router": { "backends": [
    { "name": "orders", "host": "orders.internal", "port": 8080 }
  ] } },
  "auth": {
    "methods": { "basic": {} },
    "scheme": { "mappings": [{
      "backend": "orders", "method": "basic",
      "authorization": { "groups": ["staff"] }
    }] },
    "order": 1
  },
  "oas": {
    "mappings": [{
      "backend": "orders",
      "specification": "/etc/kerberos/oas/orders.yaml",
      "options": { "validateBody": true }
    }],
    "order": 100
  }
}
Integrate

Your backend knows who is calling.

For every authenticated request, Kerberos tells the backend who the caller is in plain request headers. Go services read them with a single middleware.

  • X-Krb-User and X-Krb-Org on every authenticated request
  • X-Krb-Groups when a group rule applies
  • Generated Go clients for the Admin and basic-auth APIs
main.go
import krbauth "github.com/trebent/kerberos/pkg/auth"

func main() {
  mux := http.NewServeMux()
  mux.HandleFunc("GET /orders", func(w http.ResponseWriter, r *http.Request) {
    user, _ := krbauth.UserFromContext(r.Context())
    org, _ := krbauth.OrgFromContext(r.Context())
    fmt.Fprintf(w, "orders for user %s in org %s", user, org)
  })

  // copies the X-Krb-* identity headers into the request context
  http.ListenAndServe(":8080", krbauth.ContextMiddleware()(mux))
}
